El proyecto utiliza **MySQL / MariaDB** para persistir la información. La base de datos consta de dos tablas principales: `usuarios` y `productos`.

---

## Esquema de Tablas

### Tabla `usuarios`
Almacena los datos de los administradores autorizados para gestionar los productos de la tienda.

| Campo | Tipo | Nulable | Extra | Descripción |
| :--- | :--- | :--- | :--- | :--- |
| `id` (PK) | `INT` | NO | AUTO_INCREMENT | Identificador único de usuario. |
| `username` (UQ) | `VARCHAR(50)` | NO | UNIQUE KEY | Nombre de usuario único para inicio de sesión. |
| `PASSWORD` | `VARCHAR(255)` | NO | - | Contraseña encriptada con `bcrypt`. |
| `nombre_completo` | `VARCHAR(100)` | NO | - | Nombre y apellido del administrador. |

### Tabla `productos`
Almacena el catálogo de productos disponibles en la tienda.

| Campo | Tipo | Nulable | Extra | Descripción |
| :--- | :--- | :--- | :--- | :--- |
| `id` (PK) | `INT` | NO | AUTO_INCREMENT | Identificador único de producto. |
| `sku` (UQ) | `VARCHAR(50)` | NO | UNIQUE KEY | Código único de referencia del producto. |
| `nombre` | `VARCHAR(100)` | NO | - | Nombre comercial del producto. |
| `descripcion` | `TEXT` | NO | - | Detalle o descripción física del producto. |
| `precio_compra` | `DECIMAL(10,2)` | NO | - | Costo unitario de adquisición. |
| `precio_venta` | `DECIMAL(10,2)` | NO | - | Precio al público final. |
| `existencia` | `INT` | NO | DEFAULT `0` | Cantidad física disponible en inventario. |
| `create_at` | `TIMESTAMP` | SÍ | DEFAULT `CURRENT_TIMESTAMP` | Fecha de creación del registro. |
| `updated_at` | `TIMESTAMP` | SÍ | ON UPDATE `CURRENT_TIMESTAMP` | Fecha de última actualización del registro. |

---

## Transacciones SQL con PDO

Para garantizar la integridad y coherencia de los datos en la base de datos (evitando registros corruptos o a medias), el modelo [ProductoModel.php](file:///c:/xampp/htdocs/TIENDA_MVC/models/ProductoModel.php) implementa **transacciones SQL** en sus métodos de escritura (`crear`, `actualizar` y `eliminar`).

### Ejemplo: Creación de un Producto
El método `crear` encapsula la inserción de datos en una transacción. Si ocurre cualquier error en el flujo de la consulta (por ejemplo, una violación de clave única en el `sku` o pérdida de conexión), los cambios son revertidos mediante `rollBack()`.

```php models/ProductoModel.php
public function crear(array $data): bool
{
    try {
        // Iniciar transacción
        $this->conexion->beginTransaction();
        
        $sql = 'INSERT INTO productos (sku, nombre, descripcion, precio_compra, precio_venta, existencia, imagen)
        VALUES (:sku, :nombre, :descripcion, :precio_compra, :precio_venta, :existencia, :imagen)';
        
        $stmt = $this->conexion->prepare($sql);
        $stmt->bindParam(':sku', $data['sku']);
        $stmt->bindParam(':nombre', $data['nombre']);
        $stmt->bindParam(':descripcion', $data['descripcion']);
        $stmt->bindParam(':precio_compra', $data['precio_compra']);
        $stmt->bindParam(':precio_venta', $data['precio_venta']);
        $stmt->bindParam(':existencia', $data['existencia'], PDO::PARAM_INT);
        $stmt->bindParam(':imagen', $data['imagen']);

        $resultado = $stmt->execute();
        
        if (!$resultado) {
            // Revertir cambios si la ejecución falla
            $this->conexion->rollBack();
            return false;
        }

        // Confirmar transacción
        $this->conexion->commit();
        return true;
    } catch (PDOException $e) {
        // Revertir cambios en caso de excepción
        if ($this->conexion->inTransaction()) {
            $this->conexion->rollBack();
        }
        return false;
    }
}
```

Este esquema de protección transaccional asegura que una operación en la base de datos sea atómica: o se aplica en su totalidad o no se aplica en absoluto.
