La aplicación implementa múltiples capas de seguridad y validación para garantizar la consistencia de los datos y restringir el acceso a usuarios malintencionados.

---

## 1. Protección contra Vulnerabilidades Comunes

### Inyección SQL (SQLi)
Toda interacción con la base de datos se realiza mediante **sentencias preparadas (Prepared Statements)** a través de PDO. Los valores dinámicos se asocian mediante `bindParam` o `bindValue`. Esto impide que datos ingresados por el usuario alteren la estructura lógica de la consulta SQL.

### Ataques CSRF (Cross-Site Request Forgery)
Para evitar que atacantes envíen peticiones maliciosas en nombre de un administrador autenticado, se utiliza un sistema de **Tokens CSRF**:
1. Al renderizar el formulario, se genera un token criptográficamente seguro y se almacena en la sesión:
   ```php views/productos/create.php
   $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
   ```
2. El formulario envía este token en un campo oculto (`<input type="hidden" name="csrf" ...>`).
3. El controlador valida el token recibido utilizando la función segura `hash_equals` para mitigar ataques de temporización:
   ```php controllers/ProductoController.php
   if (!isset($_POST['csrf']) || !isset($_SESSION['csrf_token']) || !hash_equals($_SESSION['csrf_token'], $_POST['csrf'])) {
       $_SESSION['error'] = 'No hay un token csrf.';
       header('Location: ../productos/create');
       exit;
   }
   ```

## 2. Control de Acceso y Sesión

Todas las rutas administrativas (`/productos/*`) están protegidas por el método `verificarSesion` del [ProductoController](file:///c:/xampp/htdocs/TIENDA_MVC/controllers/ProductoController.php):

```php controllers/ProductoController.php
private function verificarSesion(): void
{
    if (session_status() === PHP_SESSION_NONE) {
        session_start();
    }
    if (!isset($_SESSION['admin'])) {
        header('Location: login');
        exit;
    }
}
```

Si un usuario no autenticado intenta acceder directamente, es redirigido inmediatamente a la pantalla de login.

## 3. Validaciones de Reglas de Negocio en Backend

Antes de persistir cualquier cambio en la base de datos, el controlador ejecuta rigurosas validaciones en el servidor:

* **Campos Obligatorios**: Se verifica que ningún parámetro esté vacío.
* **Tipos Numéricos**: Se asegura de que los precios y las existencias sean números válidos (`is_numeric`).
* **Valores No Negativos**: No se permiten montos negativos para precios ni existencias.
* **Regla de Precios**: El precio de venta debe ser obligatoriamente **mayor o igual** al precio de compra.
* **Regla de Stock Inicial**: Al registrar un nuevo producto, la existencia inicial debe ser **mayor a cero**.
* **Evitar SKU Duplicado**: El sistema realiza una consulta previa a la base de datos para confirmar que el SKU ingresado no exista:
  ```php controllers/ProductoController.php
  if ($this->validarDuplicado($data['sku'])) {
      $_SESSION['error'] = 'El SKU ya está registrado.';
      header('Location: ../productos/create');
      exit;
  }
  ```

## 4. Registro de Auditoría (Logs)
Las acciones administrativas clave se registran en un archivo local de auditoría llamado [logs.log](file:///c:/xampp/htdocs/TIENDA_MVC/logs.log) para llevar un control de qué usuario realizó qué cambios:

```php
// Ejemplo de registro al agregar un producto
$message = "El usuario ".$_SESSION['admin']['username']." agrego el producto ".$data['nombre']." \n";
file_put_contents('logs.log', $message, FILE_APPEND);
```
